- 可见画布实际检查：上光、侧光、底光与双色双灯；前景手臂对头部/躯干的遮挡、背景接收投影、软硬阴影、深度及原图对比视图。

## 性能

1024×1536 图像，阴影开启；交互期间阴影 512×768、48 步、1 个光源面积样本。停止后切换 96 步/更多面积样本；PNG 导出使用全分辨率阴影。

| 测试 | 帧数 | 观测 FPS |
|---|---:|---:|
| 单灯基准 | 90 | 180.02 |
| 双灯基准 | 90 | 180.02 |
| 八灯基准 | 60 | 158.43 |

可见 UI 持续动画采样：单灯预热后约 151、166、176 FPS；双灯约 153、180、178、153 FPS。单灯/双灯本机短时稳定采样约 150–180 FPS，满足 30 FPS 目标。

这是浏览器帧调度与渲染测试，不是 GPU timer-query 测量；不能把极小的 CPU 提交耗时当作真实 GPU 单帧耗时。结果不代表低端 GPU、完整分辨率多灯导出或其他浏览器表现。长时间连续手动拖动未单独形成统计，以上基准与可见动画持续更新同一交互渲染路径。

## 测试中修正的问题

- Three.js 着色器前缀与自定义 `luminance` 重名，导致实际 GPU 编译失败：移除重复定义，真实浏览器重测通过。
- 半精度高度缓存求导产生条纹：高度缓冲改用 float32，避免深度梯度量化。
- 开发环境首次加载 Worker 引发依赖预构建重载：显式预构建 Transformers.js。
- Windows 对写入中的验证 PNG 执行文件监听时 `EBUSY` 导致 Vite 退出：忽略 verification、.cache、test-results 文件监听；恢复服务后 WebGPU 再次推理成功，重新保存截图后服务仍正常。

## 隐私与未完成的验收边界

源码无图片上传接口。主图通过本地文件解码后传给本地 Worker；外部资源用于下载模型，浏览器缓存模型不保存用户图片。未完成覆盖 Worker 子目标的完整网络抓包，因此不把源码检查表述为全流量审计。

以下仍未形成完整实测证据：冷缓存断网、物理禁用 WebGPU 的设备、长时间驱动显存压力、用户实际 Blender EXR 数据集、用户角色画风质量。WASM 成功不等同物理无 WebGPU 设备验收；生成 EXR 往返单元测试不等同 Blender 生产管线验收。

单层高度场没有图外或隐藏几何；原图已有阴影不能自动彻底消除。准确外部深度/相机空间法线更适合 Blender 工作流。当前为可运行首版，不声称与原作者未知算法一致或已逐像素复刻视频。
